# 후속 확장 참고 설계

이 문서는 현재 MVP에 포함되지 않았거나 추가 범위 합의가 필요한 설계를 보관합니다.
아래의 ‘확정’은 해당 기능을 도입할 때 사용할 기존 정책을 뜻하며, MVP 구현 대상으로 확정됐다는 뜻은 아닙니다.
현재 범위는 [도메인 문서](domain-model.md#축소-mvp--2026-10-14-확정)를 우선합니다. 확장 기능을 채택하면 관련 정책·API·스키마를 각 기준 문서로 이동합니다.

## 동아리 탈퇴 신청·승인 — 추후 확장

- 기존 부원 등록·명단 조회는 [현재 MVP](domain-model.md#동아리-가입-관계--확정)에 포함합니다. 본인 탈퇴 신청·승인·거절·신청 취소와 개별 탈퇴 처리 API 및 신청 저장 구조는 MVP에서 구현하지 않습니다.
- 탈퇴 절차와 승인 주체는 추후 확장 시 결정하며 MVP 구현의 선행 조건으로 두지 않습니다.
- 아카이브에 따른 LEFT 일괄 전환과 재활성화 후 ADMIN 재가입 등록은 기존 운영 정책으로 유지합니다.

## 소모임 확장

같은 소모임에 다음 회차를 수동 추가하는 기능은 [현재 MVP](domain-model.md#소모임과-개최-회차--확정)에 포함합니다. 이 절은 자동 반복·승인제·고정 멤버 확장을 위한 참고 설계입니다.

### 소모임 관계와 권한 — 확정

- Gathering은 일회성·기간제·정기 모임을 지원하며 Club·ClubManager와 연결하지 않습니다.
- 로그인한 일반 사용자가 생성하며 생성자가 주최자입니다. 현재 MVP에서는 생성자가 모임 글·첫 회차와 후속 회차를 등록하며 글 수정·승인 기능은 제공하지 않습니다.
- 소모임은 동아리 활동도에 포함하지 않습니다.
- MVP는 FIRST_COME(선착순 즉시 확정)만 사용합니다. APPROVAL 선택과 승인·거절은 후속 확장입니다.
- 총정원에 주최자를 포함합니다. 고정 멤버 방식은 모임 생성 시 주최자의 가입 관계를, 두 방식 모두 회차 생성 시 주최자의 회차 참여 관계를 CONFIRMED로 생성합니다.
- 정원은 CONFIRMED 인원으로 계산하며 PENDING은 자리를 예약하지 않습니다.
- MVP는 선착순 참가·재참가 시 잔여 정원을 검증합니다. 동시 요청에서도 정원을 초과하지 않아야 합니다. 승인제 승인 시 검증은 후속 확장 설계입니다.
- 주최자는 개별 참여 취소가 불가능하며 모임 전체를 취소해야 합니다.
- 모임 전체 취소와 개인의 신청 취소는 구분합니다. 취소된 모임은 신청·승인을 받지 않으며 참가자를 자동으로 결석 처리하지 않습니다.

### 신청 상태와 재신청

MVP는 CONFIRMED/CANCELLED와 선착순 참가·취소·재참가만 구현합니다. 아래 PENDING/REJECTED·승인제 관련 규칙은 후속 확장 참고 설계입니다.

| 상태 | 의미 |
| --- | --- |
| PENDING | 승인 대기 |
| CONFIRMED | 참여 확정 |
| REJECTED | 주최자가 거절 |
| CANCELLED | 사용자가 신청·참여 취소 |

- FIRST_COME 신청은 정원 내에서 CONFIRMED, APPROVAL 신청은 PENDING으로 시작합니다.
- 승인제의 PENDING은 주최자 승인 시 CONFIRMED, 거절 시 REJECTED로 변경합니다.
- 일반 참가자는 PENDING·CONFIRMED 상태에서 본인 신청을 CANCELLED로 변경할 수 있습니다. 주최자는 예외입니다.
- REJECTED·CANCELLED에서 재신청을 허용하며 기존 관계를 재사용합니다.
- 재신청도 현재 신청 방식과 모집 조건을 따릅니다. PENDING·CONFIRMED의 중복 신청은 거절합니다.
- 고정 멤버 가입은 UNIQUE(gathering_id, user_id), 회차 참여는 UNIQUE(session_id, user_id)를 유지합니다.
- 신청 방식 변경은 주최자 외 신청 이력이 생긴 후 금지하는 방향입니다. 주최자 자동 등록을 최초 신청으로 취급하면 생성 직후부터 변경이 불가능하므로 제외합니다.
- 별도 빈자리 대기열은 만들지 않습니다. PENDING은 주최자의 승인을 기다리는 상태입니다.

## 글 수정과 일정 변경

활동·공지·소모임 글 수정, 참가 후 개최 시각·장소·정원·모집 마감 변경은 MVP에서 제외합니다. 확장 시 기존 참가자의 처리·변경 제한·안내 방법을 함께 설계합니다. 아래 주최자 변경도 후속 기능입니다.

### 활동 주최자 변경 — 확정

- 활성 동아리의 현재 관리자가 주최자를 변경할 수 있습니다. 아카이브 상태에서는 기존 변경 제한에 따라 허용하지 않습니다.
- 새 주최자가 참가자로 등록되어 있지 않으면 ActivityParticipant를 자동 생성하고 출결을 UNCHECKED로 설정합니다. 이미 참가자라면 기존 관계와 출결을 그대로 유지하며 중복 등록하지 않습니다.
- 기존 주최자는 참가자로 남으며 기존 출결·마지막 체크 사용자·시각을 보존합니다. 주최자 변경만으로 참가 관계를 제거하거나 출결을 초기화하지 않습니다.
- 참가자 명단·출결 관리 권한은 변경 완료 시 새 주최자에게 이전합니다. 기존 주최자는 주최자 지위에 따른 관리 권한을 잃습니다.
- 최초 작성자(author_id)는 변경하지 않습니다.
- 주최자 변경과 새 주최자의 필요한 참가 관계 생성은 같은 트랜잭션에서 처리합니다.

## 운영 상태와 활동도 — 확정

운영 상태와 활동도는 서로 다른 정보입니다.

| 항목 | 값 | 결정 방식 |
| --- | --- | --- |
| 운영 상태 | 활성(ACTIVE) / 아카이브(ARCHIVED) | 운영진이 직접 변경 |
| 활동도 | 활발 / 보통 / 활동 기록 부족 | 최근 90일의 실제 활동일을 기준으로 계산 |

- 운영 상태는 활성과 아카이브 두 가지로만 구분하며 휴면 상태를 두지 않습니다. 활동이 적다는 이유로 운영 상태를 자동 변경하지 않습니다.

### 활동도 계산

| 최근 90일 활동 건수 | 표시 |
| --- | --- |
| 3건 이상 | 활발 |
| 1~2건 | 보통 |
| 0건 | 활동 기록 부족 |

- 게시물 등록일 대신 Activity.starts_at의 Asia/Seoul 기준 개최일을 사용합니다.
- 조회 시점의 한국 날짜(`Asia/Seoul`)를 오늘로 삼아 오늘−89일부터 오늘까지 양 끝 날짜를 포함한 90일을 집계합니다. 오늘−90일의 활동은 제외하고 오늘의 활동은 포함합니다.
- 공지사항·소모임·미래 활동은 집계에서 제외합니다.
- 활동도가 낮아져도 운영 상태를 자동으로 변경하지 않습니다.
- 화면에는 `최근 90일 실제 활동일 기준`을 안내합니다.
- 기록이 없다는 이유만으로 실제 활동이 없다고 단정하지 않습니다.
- 활동도는 별도 저장 값 대신 조회 시 현재 저장된 활동일로 계산합니다. 활동일 수정이 완료되면 다음 조회부터 변경된 날짜가 집계에 즉시 반영됩니다.
- [삭제된 활동](#활동공지-삭제와-기록-보존--확정)은 집계에서 제외합니다. 삭제가 완료되면 다음 조회부터 활동도에 즉시 반영됩니다.

## 동아리 모집 설정

### 모집 계획 취소 — 확정

- 모집 계획 취소는 동아리 모집 자체를 진행하지 않기로 하고 모집 계획 여부를 false로 변경하는 것입니다. 표시 상태는 모집 안 함(NOT_RECRUITING)이 됩니다.
- 취소할 때 시작일·종료일·지원 방법·지원 링크를 모두 비우고 조기 마감 여부를 false로 초기화합니다. 모집 계획 변경과 값 초기화는 한 트랜잭션에서 처리합니다.
- 기존 모집 값을 숨겨서 보관하거나 다음 모집에 자동 복원하지 않습니다. 새 모집은 필요한 정보를 다시 입력해야 합니다.
- 조기 마감은 모집 계획과 안내를 보존하면서 마감하는 것으로, 모집 계획 취소와 구분합니다. 아카이브에 따른 마감도 계획 취소로 취급하지 않습니다.
- 취소 권한과 운영 상태에 따른 변경 제한은 모집 정보 수정에 적용되는 기존 정책을 따릅니다.

## 게시 및 아카이브 정책 — 확정

- 활동·공지는 임시저장 없이 등록 즉시 공개합니다.
- 동아리는 물리 삭제하지 않고 아카이브 상태로 보존합니다.
- 운영진만 아카이브·재활성화할 수 있습니다.
- 아카이브 동아리는 일반 목록에서 기본 제외하고 아카이브 목록에서 조회합니다. 기존 동아리 상세와 삭제되지 않은 활동·공지는 열람할 수 있습니다.
- 아카이브 상태에서는 모집할 수 없습니다. 모집 계획이 있으면 마감 처리하고, 없으면 모집 안 함을 유지합니다.
- 아카이브 전환 시 해당 동아리의 모든 ACTIVE ClubMember를 LEFT로 변경하고 left_at을 전환 시각으로 기록합니다. 승인 운영자·가입 시각·관계 최초 생성 시각은 보존하고 updated_at은 갱신합니다. 기존 LEFT 관계의 탈퇴 시각은 덮어쓰지 않습니다.
- 동아리 운영 상태 전환·모집 마감·회원 일괄 탈퇴는 같은 트랜잭션에서 처리하여 일부만 반영되지 않도록 합니다.
- 기존 활동 참가자·출결 기록은 회원 탈퇴와 별개로 보존합니다.
- 재활성화 시 동일한 동아리 ID와 과거 기록을 유지하되 기존 LEFT 회원을 자동으로 재가입시키지 않습니다. 다시 가입하려면 ADMIN의 재가입 등록이 필요합니다.
- 기존 관리 권한은 자동 삭제하지 않으며 운영진이 검토·변경합니다. 재활성화에 관리자를 필수로 요구하지는 않습니다.
- 운영 중으로 전환해도 과거 모집은 자동으로 다시 열리지 않습니다. 관리자가 새 모집 정보를 설정해야 합니다.
- 새 기수는 우선 관리자 변경과 새 모집으로 처리합니다. 별도 기수·아카이브 테이블은 만들지 않습니다.

### 상태별 변경 허용 범위 — 확정

| 대상 | 활성(ACTIVE) | 아카이브(ARCHIVED) |
| --- | --- | --- |
| 동아리 소개·기본 정보 | 해당 동아리 관리자가 수정 가능 | 수정 불가 |
| 모집 정보 | 해당 동아리 관리자가 설정·수정 가능 | 설정·수정 불가 |
| 활동·공지 | 해당 동아리 관리자가 등록·수정·삭제 가능 | 신규 등록·수정·삭제 불가 |
| 기존 활동의 참가자·출결 | 현재 지정된 활동 주최자가 관리 | 현재 지정된 활동 주최자가 정정 가능 |

- 아카이브 후에도 기존 공개 정보는 열람할 수 있으며 참가자·출결 명단은 기존 조회 권한을 유지합니다.
- 활동 주최자 변경은 활동 수정에 해당하므로 아카이브 상태에서는 허용하지 않습니다.
- 운영진이나 동아리 관리자라는 이유만으로 참가자·출결 정정 권한을 얻지 않습니다. 해당 활동의 현재 주최자여야 합니다.
- 참가자 제거 정책은 별도 확정 전까지 보류합니다. 아카이브 후 정정 허용이 게시물 삭제 권한을 추가하지는 않습니다. 삭제된 활동의 변경 제한은 아래 삭제 정책을 따릅니다.

### 활동·공지 삭제와 기록 보존 — 확정

삭제 버튼·삭제 API는 축소 MVP에서 구현하지 않습니다. 활동·공지·소모임에 deleted_at을 준비하고 미삭제 데이터만 일반 목록·상세에서 조회합니다. 아래 삭제 실행·권한·기록 보존 규칙은 삭제 기능을 후속 구현할 때 적용합니다. 본인 참가 취소 API는 게시물 삭제 기능과 별개로 MVP에 포함합니다.

- 활동·공지는 DB에서 물리 삭제하지 않고 삭제 시각을 기록하여 삭제됨으로 처리합니다. 일반 목록에서 제외하고 일반 상세 조회도 허용하지 않습니다.
- 활성 동아리의 현재 관리자가 삭제할 수 있습니다. 운영진도 해당 동아리의 관리자 권한이 필요하며, 최초 작성자라는 이유만으로 삭제 권한을 얻지 않습니다.
- 아카이브 상태에서는 활동·공지를 삭제할 수 없습니다. 삭제 복원은 MVP에서 지원하지 않습니다.
- 활동 삭제 시 참가 관계·출결·마지막 체크 사용자·시각을 그대로 보존합니다. 삭제 완료 후 활동 수정·주최자 변경·참가자 등록 및 출결 체크·정정은 차단합니다.
- 삭제된 활동의 참가·출결 기록은 본인의 참여 내역과 해당 활동의 현재 주최자 관리 화면에서만 조회할 수 있습니다. 일반 참가자는 다른 사람의 기록을 볼 수 없으며, 운영진·동아리 관리자 역할만으로 관리 명단을 조회할 수 없습니다.
- 삭제된 활동은 활동도 집계에서 즉시 제외합니다. 기록 보존 기간과 영구 파기 절차는 팀원 합의 전까지 보류하며 MVP 자동 삭제 작업을 두지 않습니다.

## 일정·참여 단위 확장

아래 유형 필드는 자동 반복·기간제·고정 멤버 도입 시의 참고 설계입니다. 현재의 수동 회차 추가에는 반복 요일·주기 설정이 필요하지 않습니다. 확장 시 진행 방식과 참여 단위, 확정 방식을 독립적으로 선택합니다.

| 축 | 값 | 의미 |
| --- | --- | --- |
| 목적·분류 | 스터디 / 프로젝트 / 해커톤·대회 / 친목 / 기타 (초안) | 모임의 목적 |
| 진행 방식 | ONE_TIME / FIXED_TERM / RECURRING | 일회성 / 기간제 / 정기 |
| 참여 단위 | PER_SESSION / FIXED_MEMBERS | 회차별 모집 / 고정 멤버 |
| 확정 방식 | FIRST_COME / APPROVAL | 선착순 / 승인제 |

- 반복 커피챗은 정기 일정과 회차별 모집, 대회 준비는 기간제와 고정 멤버를 조합할 수 있습니다.
- 기간제도 반복 일정을 가질 수 있습니다. 반복 규칙과 실제 회차는 별개로 저장합니다.
- 일회성도 실제 회차 하나를 사용합니다. 정기 모임의 예외 일정·휴회는 해당 회차에서 처리합니다.
- PER_SESSION은 회차마다 신청·정원·취소·출결을 관리합니다. 이전 회차 참가자에게 다음 자리를 자동 부여하지 않습니다.
- FIXED_MEMBERS는 모임에 한 번 가입하고 회차별 참가 대상과 출결을 관리합니다.
- 가입과 회차 참여는 별도 테이블로 분리합니다. session_id의 NULL 여부로 행의 의미를 바꾸는 통합 방식은 채택하지 않습니다.
- 불참·결석만으로 고정 멤버 자격을 자동 해제하지 않습니다. 지난 회차의 결석 자리를 소급 모집하지 않습니다.

### 모집 공개와 일정

- 모집은 대상 시작 시각 최소 2시간 전에 공개해야 합니다. 즉시 공개는 현재 시각, 예약 공개는 예약 시각을 기준으로 검증합니다.
- PER_SESSION은 각 회차 시작 시각, FIXED_MEMBERS의 최초 모집은 첫 회차 시작 시각을 기준으로 합니다.
- 공개 시각을 과거로 입력하여 제한을 우회할 수 없습니다. 공개·일정 변경 시 서버에서 재검증합니다.
- 참가·취소 시각 조건은 [현재 일정 정책](domain-model.md#일정과-표시)을 따릅니다. 확장 시에도 별도 합의 없이 취소 가능 시간을 늘리지 않습니다.
- 모집 마감은 시작 이전으로 설정하며 주최자의 조기 마감을 허용합니다.
- 이미 확정된 인원보다 정원을 줄일 수 없습니다.
- 정원이 찬 경우 신규 신청은 막고, 승인 대기는 유지합니다. 정원 검증은 승인 시에도 수행합니다.
- 회차 취소와 전체 모임 취소를 구분합니다. 전체 취소는 모든 미래 회차의 모집·개최를 중단하며 과거 출결은 보존합니다.
- 소모임 주최자는 MVP에서 변경하지 않습니다. 출결은 [기본 출결](domain-model.md#기본-출결--확정)을 따르며 시작 시각에 따른 입력 제한은 두지 않습니다.

### 동아리 적용 범위

동아리 분류는 규모가 커지거나 탐색 요구가 생기면 재검토합니다. 현재 탐색은 [공개 조회 정책](domain-model.md#기존-동아리-조회-정책)을 따르며 소모임 목적 분류는 별도의 결정 사항입니다.
동아리 정기 일정 안내는 필요하며 지속되는 조직 자체를 일회성으로 취급하지 않습니다.
동아리 활동의 반복 묶음·기간제 구조는 별도 후속 설계이며, 기존 관계 설계에는 소모임 회차 구조를 반영합니다.
동아리 정기 일정의 구조화 필드는 아직 확정하지 않았습니다.

## 후속 API 초안

아래는 모두 미구현·추가 범위 합의 대상입니다. 기본 경로는 `/api/v1`이며 [공통 API 원칙](api-endpoints.md#공통-원칙)을 따릅니다.

### 사용자·내역 조회

| 메서드 | 경로 | 기능 | 권한 |
| --- | --- | --- | --- |
| GET | /me/clubs | 관리하는 동아리 | 로그인 |
| GET | /me/gatherings | 주최 소모임 및 고정 멤버 신청 내역, 필터 구분 | 로그인 |
| GET | /me/gathering-sessions | 회차별 참여 내역·본인 출결 | 로그인 |

| GET | /clubs/{clubId}/organizer-candidates?intraLogin=... | 활동 주최자 지정 대상 검색 | 해당 동아리 관리자 |
| GET | /activities/{activityId}/participant-candidates?intraLogin=... | 활동 참가자 등록 대상 검색 | 해당 활동 주최자 |

검색 결과는 내부 ID·Intra 로그인명·표시 이름으로 제한하는 초안입니다.
부원 등록·가입 현황 조회 API는 [현재 API 명세](api-endpoints.md#동아리-부원-관리)를 따릅니다.

### 소모임 운영 API

| 메서드 | 경로 | 기능 | 권한 |
| --- | --- | --- | --- |

| PUT | /gatherings/{gatheringId}/cancellation | 전체 모임 취소 | 해당 소모임 주최자 |
| PATCH | /gathering-sessions/{sessionId} | 회차 일시·장소·정원 수정 | 해당 소모임 주최자 |

| PUT | /gathering-sessions/{sessionId}/recruitment | 회차별 모집 공개·마감 설정 | 해당 소모임 주최자 |

고정 멤버 모집은 FIXED_MEMBERS, 회차별 모집은 PER_SESSION에만 적용합니다. 자동 회차 생성 범위·중복 방지·예약 공개는 확장 시 설계합니다.

### 고정 멤버 가입 — FIXED_MEMBERS 전용

| 메서드 | 경로 | 기능 | 권한 |
| --- | --- | --- | --- |
| POST | /gatherings/{gatheringId}/participants | 본인 가입 신청·재신청 | 로그인 |
| GET | /gatherings/{gatheringId}/participants/me | 본인 가입 상태 | 로그인 본인 |
| GET | /gatherings/{gatheringId}/participants | 신청자·멤버 관리 목록 | 해당 소모임 주최자 |

참여 취소·탈퇴 경로는 중도 탈퇴가 미래 회차에 미치는 영향과 허용 시점을 정한 뒤 추가합니다.
최초 모집 취소·재신청 허용 원칙은 유지합니다. 주최자 개별 탈퇴는 허용하지 않습니다.
회차 명단 반영은 서버에서 처리하며 고정 멤버의 회차별 별도 신청·승인은 받지 않습니다.

### 회차 승인 API

| 메서드 | 경로 | 기능 | 권한 |
| --- | --- | --- | --- |
| PATCH | /gathering-sessions/{sessionId}/participants/{userId}/decision | PENDING 승인·거절 — MVP 제외 | 해당 소모임 주최자 |

FIXED_MEMBERS의 본인 회차 상태도 `/gathering-sessions/{sessionId}/participants/me`로 조회하는 초안입니다. 출결이 있는 회차 관계의 재신청은 409로 처리합니다.

## 후속 스키마

[현재 ERD](erd.md)의 테이블에 아래 관계·필드를 추가하는 참고 설계입니다. 실제 마이그레이션은 아직 없습니다.

### gathering_participants — 고정 멤버 가입

| 컬럼 | 타입 | 필수 | 의미 |
| --- | --- | --- | --- |
| id | BIGINT | O | PK |
| gathering_id | BIGINT | O | FK → gatherings.id |
| user_id | BIGINT | O | FK → users.id |
| status | VARCHAR(20) | O | PENDING / CONFIRMED / REJECTED / CANCELLED |
| created_at | TIMESTAMPTZ | O | 최초 가입 관계 생성 시각 |
| updated_at | TIMESTAMPTZ | O | 마지막 변경 시각 |

- UNIQUE(gathering_id, user_id). FIXED_MEMBERS에만 사용하며 PER_SESSION은 이 테이블에 행을 만들지 않습니다.
- 참여 방식에 따른 사용 제한과 주최자 등록은 FK만으로 보장되지 않으므로 서비스 트랜잭션에서 검증합니다.

### 소모임 확장 필드

| 테이블 | 필드 | 참고 설계 |
| --- | --- | --- |
| gatherings | schedule_type VARCHAR(20) NOT NULL | ONE_TIME / FIXED_TERM / RECURRING |
| gatherings | participation_mode VARCHAR(20) NOT NULL | PER_SESSION / FIXED_MEMBERS |
| gatherings | join_policy VARCHAR(20) NOT NULL | FIRST_COME / APPROVAL |
| gathering_session_participants | status VARCHAR(20) NOT NULL | 승인제 도입 시 PENDING / CONFIRMED / REJECTED / CANCELLED |

기간제에도 반복 규칙을 적용할 수 있으며 실제 회차와 규칙은 별도 저장합니다. 규칙 변경만으로 기존 회차를 일괄 변경하지 않습니다.
신청 방식·참여 단위는 주최자 외 신청 이력이 생기기 전에만 변경하는 방향입니다.
고정 멤버의 정원은 gatherings.capacity를 사용하며 회차 명단 반영 시점·중도 가입·불참 규칙은 확장 시 확정합니다.
목적 분류·운영 기간·반복 규칙·전체 취소·고정 멤버 모집 기간의 상세 컬럼은 미정입니다.

### 확장 인덱스

| 테이블 | 키 | 목적 |
| --- | --- | --- |
| gathering_participants | UNIQUE(gathering_id, user_id), INDEX(user_id) | 고정 멤버 중복 방지·내 가입 조회 |

## 확장 시 결정할 사항

- 동아리 정기 일정의 구조화 필드
- 소모임 목적 분류의 최종 목록, 반복 요일·간격·시간대의 표현과 회차 생성 범위
- 고정 멤버의 회차 명단 반영 시점, 한 회차 불참·탈퇴·중도 가입 규칙과 첫 회차 이후 추가 모집의 2시간 기준
- 소모임 전체 취소 후 복원 여부, 신청·승인 가능 최종 시각의 상세 경계
- 활동 참가자 제거 정책

탈퇴·블랙홀·출결 고도화와 기록 보존 기간의 상태는 [MVP 제외·보류 목록](domain-model.md#추후-확장-기능--mvp-제외)에서 관리합니다.
