# 42 로그인 구현 정리

42경산 교육생과 직원이 42 계정으로 로그인하고 서버 세션으로 인증된 API를 사용할 수 있도록 구현했습니다.
이 문서는 이미 develop에 반영된 구현의 검토 기록입니다. 이후 정책·계약은 아래 기준 문서를 따릅니다.

- [b2f5e21: 환경변수 및 로컬 OAuth 확인 절차](https://github.com/42-clubs/42-clubs-BE/commit/b2f5e21a83463bf7449e245a0011e43fbf73ccd5)

## 구현 결과

- 42 OAuth 인증 후 이메일 도메인을 정확히 비교하여 `student.42gyeongsan.kr` 교육생 계정과 `42gyeongsan.kr` 직원 계정을 허용합니다. 이메일은 저장하지 않습니다.
- 최초 로그인 시 교육생·직원 모두 42 고유 ID로 USER 계정을 생성하며 재로그인 시 이름·로그인명을 갱신하고 내부 ID·역할을 유지합니다. 동시 최초 로그인에서 중복 계정 생성을 방지합니다.
- 로그인 성공 시 세션 ID를 교체하고 성공 URL로 이동합니다. 로그인 이후 42 API 토큰과 원본 프로필을 저장하지 않습니다.
- 내 정보 조회, CSRF 토큰 조회 및 로그아웃을 제공합니다. 변경 요청에는 CSRF 헤더가 필요하며 로그인·로그아웃 후 토큰을 다시 조회합니다.
- ADMIN API 접근을 제한하고 매 요청 DB의 현재 역할을 확인합니다. 사용자 행이 없어지면 기존 세션을 무효화합니다.
- 설정된 프론트엔드 origin에만 쿠키를 포함한 CORS 요청을 허용합니다.

구체적인 경로·응답·오류 계약은 [인증 API 명세](api-endpoints.md#인증--구현-계약),
계정 생성·역할·세션 정책은 [로그인 정책](domain-model.md#로그인-및-인증--확정)을 따릅니다.

## 검증 범위

[AuthIntegrationTests](../src/test/java/com/clubplatform/auth/AuthIntegrationTests.java)는 로컬 OAuth 제공자와 실제 PostgreSQL 테스트 컨테이너로 다음 동작을 검증합니다.

- 최초·반복·동시 로그인과 사용자 역할·ID 보존
- 교육생·직원 도메인 허용과 USER 역할 생성, 타 캠퍼스·유사 이메일 접미사·잘못된 프로필 거부와 도메인 대소문자 처리
- 잘못된 OAuth state·인가 요청 누락·코드 교환 실패 처리
- 로그인 시 세션 ID 교체와 이전 CSRF 토큰 무효화
- CSRF 없는 로그아웃 거부 및 정상 로그아웃 후 세션 무효화
- 비로그인 내 정보 조회 거부와 공개 동아리 조회 유지
- 현재 DB 역할에 따른 ADMIN 접근, 사용자 삭제 시 세션 무효화, 허용 origin CORS

실제 42 자격증명을 이용한 연동은 별도로 확인해야 합니다. 로컬 테스트는 실제 42 서버 연동 검증을 대신하지 않습니다.

## DB·환경변수·문서 영향

- 기존 users 스키마를 사용하며 로그인 구현의 추가 DB 마이그레이션은 없습니다.
- 인증 활성화·42 자격증명·콜백·성공 URL·허용 origin·쿠키 설정은 [.env.example](../.env.example)과 [환경변수 문서](environment-variables.md)에서 관리합니다. 실제 비밀값은 저장소에 포함하지 않습니다.
- 실행·프론트엔드 연결 방법은 [README 로그인 안내](../README.md#42-로그인-실행), 기능 간 책임은 [아키텍처](architecture.md)와 [모듈 가이드](module-development.md)를 참고합니다.

## 후속 확인과 MVP 범위

- 서비스용 42 OAuth 앱의 자격증명과 등록 콜백을 설정한 뒤 실제 로그인·재로그인·로그아웃을 확인합니다.
- 프론트엔드의 쿠키 포함 요청·CSRF 처리와 배포 환경의 HTTPS·origin·쿠키 설정을 확인합니다.
- 최초 ADMIN은 운영자가 DB에서 지정합니다. 서버 메모리 세션이므로 재시작 시 재로그인이 필요합니다.
- 블랙홀 판정·개인정보 제거·이용 차단은 [추후 확장](domain-model.md#추후-확장-기능--mvp-제외)으로 두며 현재 MVP 로그인에는 포함하지 않습니다.
- 기록 보존 기간·영구 파기 절차는 [팀 합의 대기](domain-model.md#팀-합의-대기--보류)입니다.
